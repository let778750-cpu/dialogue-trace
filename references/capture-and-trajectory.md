# 记录、整理与轨迹详情

原样记录由确定性的本地脚本完成，不调用模型。Skill 负责进入研究任务、检查采集缺口、读取增量、整理和发布的工作约定；它不是常驻进程。安装协议不能保证每一轮的宿主 hooks 已获信任或被调用。

| 工作 | 执行方式 | 模型开销 |
|---|---|---|
| 保存公开消息、工具输入输出、来源定位、哈希与游标 | hook / 指定转录文件补核 | 不增加模型调用 |
| 分类明确的环境封套、关联明确调用 ID、构建索引 | 规则与版本化投影 | 不增加模型调用 |
| 判断研究线、结果意义、矛盾和下一步 | 当前会话模型按批整理 | 有上下文及生成开销 |
| 恢复研究状态 | 轻量版本核对，有变化才读取有界增量 | 与实际读取量有关 |

首版不运行低价模型旁路。让第二个模型持续读完整对话会重复消耗上下文，并增加漏记、误归属、并发状态和凭据管理问题。未来若添加可选的低成本整理器，应只生成带来源的候选，不负责事实归档、不覆盖原文，也不自动发布科学结论；须单独验证召回率和节省比例。本版没有配置或启动这类模型。

官方 [skill 文档](https://learn.chatgpt.com/docs/build-skills)公开的元数据包括界面、调用策略和工具依赖，没有给 skill 声明一个常驻记录模型的字段。模型选择和子代理运行属于宿主能力，不应通过虚构的 YAML 配置实现。官方 [hooks 文档](https://learn.chatgpt.com/zh-Hans/docs/hooks)还明确区分 hook 配置、信任与实际执行，并提示转录格式不是稳定接口。

## 借鉴 Harness 的范围

参考 DeepSeek Harness 的 [Trajectory 实现说明](https://github.com/deepseek-ai/deepseek-harness/blob/0d1f50007f9bca3f52b06e1c3074fa14d5fb0720/packages/client/ui-trajectory/README.md)及[会话投影架构](https://github.com/deepseek-ai/deepseek-harness/blob/0d1f50007f9bca3f52b06e1c3074fa14d5fb0720/.agents/notes/archived/architecture/2026-08-11-trajectory-conversation-context-assembly.md)。此处采用设计原则，未复制其实现源码。

- 同一事件事实源供不同阅读界面使用；主研究时间线与技术详情共用来源 ID。
- 用户、助手、上下文、工具、生命周期使用不同的详情结构。
- 工具的输入、结果、工具定义和时序分别展示；唯一明确的调用 ID 才用于关联。重复调用标识标注歧义。
- 原始字段和可读预览分开；长工具内容按需读取。
- 未记录的时间、用量或工具定义显示未知。发生时间和入库时间之差不算执行耗时。
- 稳定的阅读锚点和分批加载；新数据不抢走正在阅读的位置。

Harness 控制模型请求和执行生命周期，能够获得更完整的回合、步骤、请求用量、流式时序及工具定义。本项目首先是跨任务、跨研究线的记忆层；Codex 适配只使用宿主公开字段。不能由截图上的“思考”标签推断 Codex 的隐藏推理可采集。本版保留公开回答和过程说明，排除私有推理；自动压缩仅记录边界与来源，不复制压缩内部提示或私有摘要。研究断点由当前模型另外发布可读的已知、未知和下一步。

## 详情接口

`research event.detail --file <包含 event_id 的 JSON>` 提供 `kind`、`classification`、`preview`、`raw_public_event`、`source`、`inputs`、`outputs`、`schemas`、`timing`、`usage` 和来源限制。只有实际归档的字段会有值。原始字段指已规范化的公开事件，不是完整模型请求。Obsidian 的“类型与来源详情”和“技术记录与来源环境”均调用此接口。
