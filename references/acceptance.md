# 预览版验收与正式切换

预览版可以在工程检查通过、使用效果未测时试用；不能据此覆盖现有正式入口。运行结果与人工效果分开记录，发行目录的 `VALIDATION.md` 写明当前证据。

## 人工找回任务

原六类：最初问题、用户补充条件、AI 修正、否定理由、实验依据、跨天恢复下一步。

新增五类：跨任务续接、混合主题归线、归属纠正、结果溯源、研究断点恢复。不同组分别评分，避免总体平均掩盖退步。

在同一份授权资料上比较新版、0.7 时间线和原始聊天。旧图谱可作为适用问题的附加基线。Harness 只有在数据与任务可比时加入，不能用功能文档代替实测。

```powershell
python scripts/retrieval_study.py init --file 'C:/ResearchMemory/study.json' --manifest release-manifest.json
python scripts/retrieval_study.py score --file 'C:/ResearchMemory/study.json' --manifest release-manifest.json --sources 'C:/ResearchMemory/study-sources.json'
```

空白模板不预填耗时和正确率。每次记录实测耗时（失败也计入）、跳转次数、答案、定位到的事件及原话。另由复核者核对正确性。`study-sources.json` 是按任务 ID 索引的答案依据，每项包含 `event_id`、完整 `text`、文本 UTF-8 的 `sha256`；只保存在私有数据目录。参与者与复核者明确身份；单人重复任务的学习效应须在解释中保留。

两个任务组都需要满足：相较本组最快基线，耗时中位数减少至少 20%，来源／答案正确数量不低于任何基线。来源改动、缺失测量、非人工记录、构建哈希不同均不能通过。评分器不会自动切换插件或宣称科学结论有效。

## 真实双任务与界面验证

1. 在已登记工作区打开两个真实 Codex 任务，明确绑定同一研究线。分别产生独特的公开补充条件，记录宿主是否实际调用 hooks。
2. 另一任务进入新一轮时检查增量；只有看到对应来源和变化才算成功。hooks 未触发时，核对该任务实际转录路径并补核，分别记录自动路径与补核路径。
3. 在其中一个任务明确创建并切换另一研究线，保留切换事件边界；补录旧消息，验证旧消息不被当前绑定覆盖。
4. 选择连续消息提出归线修正，确认后应用并撤销。检查另一入口的版本冲突及原话不变。
5. 用 Obsidian 实测长文、表格、代码、附件状态、深浅主题与窄窗口；检查类型化详情、搜索定位、返回、刷新和重开。初始化信任与插件执行由用户决定。

真实历史重放、独立 CLI/MCP 客户端、单元测试都不能替代真实任务 hooks 验收。10,000 条数据的投影、首屏、增量加载与搜索需要分别报告；没有实际渲染测量就不填写 UI 耗时。
